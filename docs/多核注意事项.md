# 多核注意事项

ltx V4 带来了多核 SMP 调度，同构多核下，可以让每个核心都重入 ltx_Sys_scheduler，只要某个核空闲，就会自己去弹出事件，自动完成负载均衡。

ltx 层面为了防止事件回调重入、不转移内存管理和避免野指针做了很多努力。  
但这并不是免费午餐，ctx 层面也做了很多努力去防止业务层面上的重入和内存问题，比如虽然 ltx 可以确保一个核心正在执行某个 topic 在弹出后执行回调时，又被发布进事件队列后，其它核会绕过它弹出下一个。但是 ctx 层面却会出现一个任务同时订阅两个 topic 的情况，比如等待事件 topic，和等待超时闹钟 topic，业务层面就会重入，所以最终是通过在 ltx 层面添加钩子将 ctx 非临界区判断的东西转移到 ltx 的临界区内实现的，没有增加多少开销，确保了业务逻辑和内存安全。

总之，没有将内存管理从 ctx 委托给 ltx，没有额外增加引用计数、gc 什么乱七八糟的

以下是一些值得注意的事项

## 1、竞争资源

在单核情况下，协程的优势是一个任务不会被另外一个任务打断，所以操作任务间共享变量是不需要进出临界区的。  
而多核下，则可能两个任务跑在两个核心内，那么此时需要用户考虑对自己的共享数据增加进出临界区操作
