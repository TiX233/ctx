# 注意事项

## 1、请不要对以下函数标注 _async：

* main 函数
* 中断服务函数
* 回调函数

因为这些函数都是被函数指针调用的，无法被翻译脚本和宏替换

`非 async 函数` 要启动一个 `async 函数`，请使用 `_start_async(obj_ptr, func, ...)` 宏，需要动态创建则 `obj_ptr` 传入 `NULL`  
`async 函数` 要启动一个与自己无关的任务也可以用这个宏

## 2、内部块不允许重名局部变量！

例如：
```c
_async void xxx(void){
    int a = 1;
    {
        int a = 9;
        printf("aa: %d\n", a);
    }
    _yield();

    printf("a: %d\n", a);
}
```

这种写法在 c 语言是合规的，但是我 **不允许** 出现这种情况  
为什么 要使用 相同的名字？平常来讲这也会导致业务代码比较混乱  
总之我不会让翻译器兼容这种情况，它们会都翻译成同一个变量，翻译结果大概如下：
```c
    _prv_data->a = 1;
    {
        _prv_data->a = 9;
        printf("aa: %d\n", _prv_data->a);
    }

    // 出让与状态流转
    // xxx

    printf("a: %d\n", _prv_data->a);
```

也就是这种代码会出 bug，需要注意

## 3、宏定义复用代码

您可能会写出如下例子的代码：

```c
// 在宏定义中调用异步函数
#define log_with_lock(str)  do{\
                            _await ctx_mutex_lock(&mutex_log, -1);\
                            log(str);\
                            _await ctx_mutex_unlock(&mutex_log);\
                            }while(0)

_async xxx(void){
    // 翻译脚本会正确翻译异步调用 abc
    _await abc();

    // 翻译脚本不会认为这是一个异步函数，从而不会进行翻译
    log_with_lock("hello\n");
}
```

用宏定义复用代码，在以往的 c 编程看起来是很自然的事，但是对于目前的翻译脚本来说，它还没有这个能力去展开宏定义，因为这不亚于实现一个编译器，而且还要再手动配置一遍头文件路径什么的。  
这个问题暂时不好解决，所以还请在出让点手动编写相关逻辑。  

如果要解决这个问题，以下是构思的可能路径：  
* 翻译脚本展开宏定义
* 接管预处理器，目前只有 gcc 似乎可以做到
* c 语言在语言层面提供异步关键字

## 4、翻译脚本变量生命周期提升注意

自 V0.7 版本的翻译脚本以后，变量生命周期改为通过起止行号来进行判断，简化了判断逻辑并且得到了较好的判断效果。

默认的生命周期判断是以所在行号的左开右闭作为判断，例如 `(12, 32]` 这种形式，如果变量处于循环体内，那么会把整个循环体都囊括在其生命周期内。  
对于变量作为异步函数传参时，如果时只取值，那么则是右开，例如 `(12, 32)`；如果是取它的地址进行传参，那么依旧保持右闭。

但是需要注意，在 c 语言中，甚至可以把所有代码写在同一行，那么这样就对 V0.7 以后的版本判断生命周期造成了困难，所以请在编写代码时规范书写，格式清晰，不仅是为了让脚本正确翻译代码，也是为了您能更好地维护您的代码。

对于 V0.8 及以后版本的翻译脚本，可以识别 `_var_local` 和 `_var_frame` 关键字，这两个空宏关键字用于给局部变量进行手动生命周期声明，让翻译结果更加灵活以及高效。  
如果要使用这两个关键字的话，需要您深刻理解协程变量的生命周期，否则代码可能会出现 bug
